Design Observer Guide

Problem

Imagine you have an object that contains some important state, and many other objects need to stay up to date whenever that state changes. For example, you have a news agency that publishes updates, and dozens of subscribers want to receive new articles.

You could just call an update method in every dependent object whenever something changes, but that leads to tight coupling: the main object would have to know about every subscriber’s class and logic.

The problem is that the publisher becomes dependent on many other classes. If you add, remove, or modify subscribers — you must constantly change the publisher’s code too.

Solution

The Observer pattern suggests that you add a subscription mechanism to your object, allowing other objects to subscribe or unsubscribe dynamically.

The object that holds the state is called the Subject, and the objects that want to be informed are called Observers.

When the Subject’s state changes, it automatically notifies all registered observers by calling one of their methods. This way, the Subject doesn’t need to know who the observers are or what they do — only that they implement a certain interface.

This decouples the Subject from its Observers, making it easy to extend or reuse both independently.

Real-World Analogy

Think of YouTube subscriptions. When a channel (Subject) posts a new video, all of its subscribers (Observers) receive a notification. The channel doesn’t need to contact each subscriber manually — it just triggers one general "notify" event.

Similarly, when you unsubscribe, the Subject simply stops sending you updates. This makes the whole system flexible and dynamic.

Structure

1. Basic Implementation

1. The Subject maintains a list of observers and provides methods for attaching and detaching them.

2. The Observer interface declares the update() method, used by subjects to notify observers.

3. The ConcreteSubject stores the state of interest and sends notifications when the state changes.

4. The ConcreteObserver reacts to updates sent by the subject.

2. Event Subscription Implementation

Many modern languages (like C# and JavaScript) have built-in support for events, which is essentially the Observer pattern in action. Objects can subscribe to events and automatically receive updates when those events occur.
