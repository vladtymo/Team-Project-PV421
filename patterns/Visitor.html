The Visitor Pattern

Represent an operation to be performed on elements of an object structure. The Visitor lets you define a new operation without changing the classes of the elements on which it operates.

When to Use

  • When you need to perform new operations on a structure of objects without modifying their classes.
  • When many unrelated operations must be performed on the same set of classes.
  • When classes form a structure and you want to separate data from behavior.

Checklist

  • Define a Visitor interface
  • Each element implements accept(Visitor v)
  • Concrete visitors implement behavior for each element type
  • Clients traverse elements and call accept()

Idiomatic Implementations

Java

interface Visitor {
  void visit(Book book);
  void visit(CD cd);
}

interface Item {
  void accept(Visitor v);
}

class Book implements Item {
  public void accept(Visitor v) { v.visit(this); }
}

class CD implements Item {
  public void accept(Visitor v) { v.visit(this); }
}

class PriceVisitor implements Visitor {
  public void visit(Book book) { System.out.println("Book price: $10"); }
  public void visit(CD cd) { System.out.println("CD price: $5"); }
}

C#

interface IVisitor {
    void Visit(Book book);
    void Visit(CD cd);
}

interface IItem {
    void Accept(IVisitor visitor);
}

class Book : IItem {
    public void Accept(IVisitor visitor) => visitor.Visit(this);
}

class CD : IItem {
    public void Accept(IVisitor visitor) => visitor.Visit(this);
}

class PriceVisitor : IVisitor {
    public void Visit(Book book) => Console.WriteLine("Book price: $10");
    public void Visit(CD cd) => Console.WriteLine("CD price: $5");
}

JavaScript

class Book {
  accept(visitor) { visitor.visitBook(this); }
}
class CD {
  accept(visitor) { visitor.visitCD(this); }
}
class PriceVisitor {
  visitBook() { console.log("Book price: $10"); }
  visitCD() { console.log("CD price: $5"); }
}
const items = [new Book(), new CD()];
const visitor = new PriceVisitor();
items.forEach(i => i.accept(visitor));

Python

class Visitor:
    def visit_book(self, book): pass
    def visit_cd(self, cd): pass

class Book:
    def accept(self, v): v.visit_book(self)

class CD:
    def accept(self, v): v.visit_cd(self)

class PriceVisitor(Visitor):
    def visit_book(self, book): print("Book price: $10")
    def visit_cd(self, cd): print("CD price: $5")

for item in [Book(), CD()]:
    item.accept(PriceVisitor())

Pros & Cons

✅ Benefits

  • Add new operations easily
  • Keeps related behavior together
  • Clean separation of algorithms from objects

⚠️ Pitfalls

  • Adding new element types is hard
  • Breaks encapsulation sometimes
  • Can get complex with many classes

Alternatives

  • Strategy: if operations are independent.
  • Command: encapsulate action in objects.
  • Double Dispatch: core mechanism used by Visitor.
