The Flyweight Pattern

Flyweight is a structural design pattern that lets you fit more objects into available RAM by sharing common parts of state between multiple objects.

Intent

Flyweight allows efficient memory usage by separating shared (intrinsic) and unique (extrinsic) object states, reducing RAM consumption when many similar objects exist.

Problem

In a game with thousands of bullets, missiles, and particles, each object held duplicated data (like color and sprite). When memory ran out, the game crashed — showing the need to share common state.

Solution

Separate the object's data into:

  • Intrinsic state — shared and immutable (e.g. sprite, color).
  • Extrinsic state — unique for each instance (e.g. coordinates, speed).

Store intrinsic data in flyweight objects and extrinsic data externally. Use a factory to manage existing flyweights and reuse them when possible.

Pseudocode


// The flyweight class stores shared (intrinsic) state
class TreeType {
    String name;
    String color;
    String texture;

    TreeType(String name, String color, String texture) { ... }

    void draw(Canvas canvas, int x, int y) {
        // Draw tree of this type at given position
    }
}

// Factory that reuses existing flyweights
class TreeFactory {
    static List<TreeType> types = new ArrayList<>();

    static TreeType getTreeType(String name, String color, String texture) {
        for (TreeType t : types)
            if (t.name.equals(name) && t.color.equals(color) && t.texture.equals(texture))
                return t;
        TreeType type = new TreeType(name, color, texture);
        types.add(type);
        return type;
    }
}

// Context class holds extrinsic state
class Tree {
    int x, y;
    TreeType type;

    Tree(int x, int y, TreeType type) { ... }

    void draw(Canvas canvas) {
        type.draw(canvas, x, y);
    }
}

// Client example
class Forest {
    List<Tree> trees = new ArrayList<>();

    void plantTree(int x, int y, String name, String color, String texture) {
        TreeType type = TreeFactory.getTreeType(name, color, texture);
        trees.add(new Tree(x, y, type));
    }

    void draw(Canvas canvas) {
        for (Tree tree : trees)
            tree.draw(canvas);
    }
}

When to Use

  • When your program must support a huge number of similar objects.
  • When RAM usage becomes critical.
  • When objects contain duplicate data that can be shared.

Pros and Cons

  • ✅ Saves a lot of RAM by sharing common state.
  • ⚠️ Increases complexity and CPU usage due to managing extrinsic data.
  • ⚠️ Harder for new developers to understand state separation.

Relations with Other Patterns

  • Can be combined with Composite to share leaf nodes.
  • Similar to Singleton when only one flyweight exists.
  • Flyweight shares small objects, Facade wraps large subsystems.
