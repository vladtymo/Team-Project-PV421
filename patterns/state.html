Патерн проектування: State (Стан)

Intent (Намір)

State — це поведінковий патерн, який дозволяє об'єкту змінювати свою поведінку залежно від внутрішнього стану. Здається, що об'єкт змінив свій клас.

Проблема

Патерн State тісно пов'язаний з концепцією кінцевого автомата (Finite-State Machine).

Кінцевий автомат

Основна ідея в тому, що у будь-який момент програма може бути у скінченній кількості станів. В залежності від стану програма поводиться по-різному, і переходить між станами за заздалегідь визначеними правилами (трансітами).

Наприклад, документ може бути у станах: Draft, Moderation та Published. Метод publish поводиться по-різному в кожному з них.

Проблеми з умовними конструкціями

Зі збільшенням кількості станів і поведінок код з множиною умовних операторів стає важким для підтримки. 

class Document {
  field state: string;

  method publish() {
    switch (state) {
      case "draft":
        state = "moderation"; break;
      case "moderation":
        if (currentUser.role == "admin")
          state = "published";
        break;
      case "published":
        // нічого не робити
        break;
    }
  }
}

Рішення

Створюємо класи для кожного стану і переносимо поведінку туди. Головний об'єкт (контекст) делегує роботу відповідному об'єкту стану.

Перехід між станами відбувається заміною об'єкту стану у контексті.

Реальний приклад

Кнопки смартфона поводяться по-різному залежно від стану пристрою: заблоковано, розблоковано чи низький заряд.

Структура

Контекст зберігає посилання на об'єкт стану та делегує йому всі станоспецифічні дії через інтерфейс.

Псевдокод прикладу

// Контекст AudioPlayer
class AudioPlayer {
  field state: State;
  
  constructor() {
    this.state = new ReadyState(this);
  }
  
  method clickPlay() {
    state.clickPlay();
  }

  method changeState(state: State) {
    this.state = state;
  }
}

// Абстрактний стан
abstract class State {
  protected player: AudioPlayer;
  constructor(player) { this.player = player; }
  abstract clickPlay();
}

// Конкретні стани
class ReadyState extends State {
  clickPlay() {
    player.startPlayback();
    player.changeState(new PlayingState(player));
  }
}
class PlayingState extends State {
  clickPlay() {
    player.stopPlayback();
    player.changeState(new ReadyState(player));
  }
}

Застосовність

  • Об'єкт поводиться по-різному залежно від свого стану.
  • Кількість станів велика, і вони часто змінюються.
  • Бажано уникнути великої кількості умовних операторів.

Плюси і мінуси

  • Покращує принцип єдиної відповідальності — логіка станів у різних класах.
  • Дозволяє легко додавати нові стани без зміни існуючих.
  • Можливо зайвий для невеликої кількості станів.

Відношення з іншими патернами

State схожий на Strategy, але дозволяє станам знати про переходи між собою.
