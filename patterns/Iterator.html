Iterator (Ітератор)

Мета: Надати спосіб послідовного доступу до елементів колекції без розкриття її внутрішньої структури.

Коли використовувати

Коли потрібно обійти складну структуру даних (масиви, списки, дерева) послідовно; якщо треба підтримувати кілька одночасних проходів по колекції або різні способи ітерації (вперед, назад, фільтрація) без зміни самих колекцій.

Структура (спрощена)

// Абстрактний інтерфейс ітератора
interface Iterator<T> {
  boolean hasNext();
  T next();
}

// Колекція повертає ітератор
interface IterableCollection<T> {
  Iterator<T> createIterator();
}

// Конкретна колекція + конкретний ітератор
class MyList implements IterableCollection<T> { ... }
class MyListIterator implements Iterator<T> { ... }

UML (мінімальне)

Client --> Iterator
Client --> Aggregate
Aggregate --> ConcreteAggregate
Iterator <|-- ConcreteIterator
Aggregate <|-- ConcreteAggregate

Приклад: C# (простий)

// Простий ітератор для масиву
public interface IIterator<T> {
    bool HasNext();
    T Next();
}

public class ArrayIterator<T> : IIterator<T> {
    private readonly T[] _items;
    private int _index = 0;
    public ArrayIterator(T[] items) => _items = items;
    public bool HasNext() => _index < _items.Length;
    public T Next() => _items[_index++];
}

public class SimpleCollection<T> {
    private readonly T[] _items;
    public SimpleCollection(T[] items) => _items = items;
    public IIterator<T> CreateIterator() => new ArrayIterator<T>(_items);
}

// Використання:
var names = new SimpleCollection<string>(new[] {"Іван","Оля","Петро"});
var it = names.CreateIterator();
while(it.HasNext()) Console.WriteLine(it.Next());

Приклад: JavaScript (ітератор + генератор)

class SimpleCollection {
  constructor(items){ this.items = items }
  // стандартний ітератор ES
  [Symbol.iterator]() {
    let index = 0; const items = this.items;
    return { next: () => index < items.length ? {value: items[index++], done:false} : {done:true} };
  }
}

const c = new SimpleCollection([1,2,3]);
for(const v of c) console.log(v);

Плюси / Мінуси

Плюси: відокремлює логіку обходу від структури даних; дозволяє різні способи обходу; підтримує одночасні обходи.

Мінуси: додає додаткові класи; може ускладнити прості колекції.

Коли не варто

Якщо колекція дуже проста (наприклад, звичайний масив з мовними циклами) — додаткові класи і код можуть бути зайвими.

Порада: у .NET і Java є вбудовані інтерфейси для ітераторів (IEnumerable/IEnumerator, Iterator), використай їх коли можеш.
