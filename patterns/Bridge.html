The Bridge Pattern

The Bridge pattern decouples an abstraction from its implementation, allowing both to evolve independently.

When to Use

  • When you want to separate abstraction from implementation so they can change independently.
  • When you have multiple variants of both abstraction and implementation.
  • When subclassing causes an explosion of classes (Cartesian product problem).

Concept Diagram (Simplified UML)

Abstraction ----------------------> Implementation
     |                                     |
     |----RefinedAbstraction               |----ConcreteImplementation

Example — JavaScript Implementation

// Implementor
class Device {
  isEnabled() {}
  enable() {}
  disable() {}
  getVolume() {}
  setVolume(v) {}
}

// Concrete Implementor
class TV extends Device {
  constructor() {
    super();
    this.on = false;
    this.volume = 30;
  }
  isEnabled() { return this.on; }
  enable() { this.on = true; }
  disable() { this.on = false; }
  getVolume() { return this.volume; }
  setVolume(v) { this.volume = v; }
}

// Abstraction
class Remote {
  constructor(device) {
    this.device = device;
  }
  togglePower() {
    if (this.device.isEnabled()) this.device.disable();
    else this.device.enable();
  }
}

// Refined Abstraction
class AdvancedRemote extends Remote {
  mute() {
    this.device.setVolume(0);
  }
}

// Demo
const tv = new TV();
const remote = new AdvancedRemote(tv);
remote.togglePower();
remote.mute();
console.log(tv);

Key Benefits

  • Abstraction and implementation can vary independently.
  • Improved code extensibility and flexibility.
  • Reduces class hierarchy complexity.

Real-World Analogy

Think of a remote control (abstraction) and a TV (implementation). You can use the same remote interface to control different devices, or upgrade devices without changing how the remote works.
